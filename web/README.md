# FleetTrack — диспетчерская

Фронтенд в виде диспетчерского мнемощита: фуры едут по федеральным трассам в реальном времени,
цвет лампы показывает состояние машины, тревоги всплывают и принимаются в работу прямо с карты.

Вокруг карты — рабочие разделы над всем REST API бэкенда: машины, водители, трекеры, рейсы с треком
и графиком скорости, журнал тревог и правила, пользователи. Что видно и что можно нажать, зависит от роли.

## Разделы

| Адрес | Что там | Эндпоинты |
| :--- | :--- | :--- |
| `/` | Карта парка в реальном времени | `GET /fleet/snapshot`, `GET /stream`, `PATCH /alerts/{id}` |
| `/vehicles`, `/vehicles/:id` | Машины; карточка с треком, графиком скорости, точками и рейсами | `/vehicles`, `/telemetry`, `/assignments` |
| `/drivers`, `/drivers/:id` | Водители и их рейсы | `/drivers`, `GET /trips?driver_id=` |
| `/devices` | Трекеры: регистрация, поиск по номеру, привязка, кто на связи | `/devices`, `POST /assignments`, `GET /telemetry` |
| `/trips`, `/trips/:id` | Рейсы: назначение, статус, трек рейса | `/trips`, `GET /telemetry?trip_id=` |
| `/alerts`, `/alerts/rules` | Журнал тревог с фильтрами и правила | `/alerts`, `/alert-rules` |
| `/team` | Пользователи организации | `/users`, `GET /organizations` |
| `/login`, `/register` | Вход и регистрация организации | `/login`, `/register`, `/refresh`, `/logout` |

Состояние API (`/readyz`) и ссылка на Swagger — внизу боковой панели. Фильтры и страница списка лежат
в адресной строке: отфильтрованный список можно отправить ссылкой.

| Роль | Видит |
| :--- | :--- |
| Администратор | всё, включая пользователей |
| Диспетчер | карта, парк, рейсы, тревоги; меняет данные и принимает тревоги |
| Аналитик | карта и все данные только для чтения |
| Водитель | свои рейсы — остальное бэк ему не отдаст |

Роль фронт читает из access-токена только чтобы не показывать кнопки, на которые придёт 403;
проверяет права бэк.

## Запуск

Два режима, переключаются переменной `VITE_FLEET_SOURCE` (см. `.env.example`).

**Симулятор** — бэкенд не нужен:

```bash
make web-install   # или: cd web && npm ci
make web-dev       # http://localhost:5173
```

**Живой бэкенд** — карта на данных Go-сервиса:

```bash
make run                                     # API на :8080 (Postgres из docker compose)
cd web && npm run sim                        # генератор парка: организация, машины, трекеры, поток точек
VITE_FLEET_SOURCE=api npm run dev            # фронт; войти данными, которые напечатал генератор
```

Генератор регистрирует новую организацию при каждом запуске и сохраняет логин в `web/.fleet-sim.local.json`
(файл в `.gitignore`). Время ускорено ×60 (`FLEET_SCALE`), но точки уходят с `device_timestamp`,
поэтому скорость, пробег и алерты бэк считает реальные. Раз в 4 минуты один трекер замолкает на 150 секунд —
это проверка `DEVICE_OFFLINE`.

**Демо-стенд в Docker** — API, фронт и генератор одной командой. В корневом `.env` задайте
`FLEET_DEMO_EMAIL` и `FLEET_DEMO_PASSWORD` (это публичная учётка витрины: пароль попадает в сборку
фронта), затем:

```bash
make demo-up       # фронт на http://localhost:8081, на экране входа — «Войти в демо-парк»
make demo-logs     # что делает генератор
make demo-reset    # удалить базу и завести демо-парк заново
```

Фронт в контейнере — nginx: он отдаёт сборку и проксирует `/api/*` на сервис `api`, поток `/api/stream`
идёт без буферизации. Без профиля `demo` (`make docker-up`) поднимается тот же фронт, но без генератора.

Проверки и сборка:

```bash
make web-check     # tsc + vitest
make web-build     # web/dist
```

## Управление

| Клавиша | Действие |
| :--- | :--- |
| `P` или `Пробел` | пауза и продолжение симуляции |
| `[` `]` | предыдущая и следующая машина |
| `F` | следить за выбранной машиной |
| `Esc` | снять выбор |

Скорость симуляции: ×1 — реальное время, ×60 — минута за секунду (по умолчанию), ×300.

## Цвета ламп

| Лампа | Состояние |
| :--- | :--- |
| янтарная | в рейсе |
| зелёная | свободна |
| синяя | на обслуживании |
| красная, мигает | тревога не принята |
| красная, ровная | тревога принята в работу |
| пустая серая | трекер молчит (`DEVICE_OFFLINE`) |

## Устройство

```text
src/
  App.tsx                  маршруты, вход по сессии, ленивая загрузка карты
  types.ts                 контракт с бэком: поля как в internal/handler/dto
  api/                     клиент с refresh-токеном, списки и страницы, перевод ошибок, кеш запросов
  sections/<раздел>/       api.ts (запросы и хуки TanStack Query) и страницы раздела
  sections/telemetry/      трек, график скорости, отправка и удаление точек
  source/FleetSource.ts    интерфейс источника данных карты: load, subscribe, acknowledgeAlert
  source/mock/             симулятор: рейсы, топливо, AlertService и OfflineWorker в миниатюре
  state/                   zustand-стор карты, селекторы, сессия и права
  map/                     MapLibre + deck.gl, интерполяция движения, маркеры, карта трека
  ui/                      каркас разделов, диалоги, фильтры, панели карты
```

Типы контракта написаны руками, а не сгенерированы из `docs/swagger.json`: swagger там версии 2.0
без `required` и `nullable`, и генератор сделал бы необязательным каждое поле.

Списки бэк отдаёт без общего числа записей, поэтому страница запрашивает на одну запись больше,
чем показывает: так видно, есть ли следующая. Часть эндпоинтов на пустой выборке отвечает `data: null`
вместо `[]` — `apiList` приводит это к массиву в одном месте.

Точки телеметрии приходят раз в секунду, а машина между ними едет плавно: `map/motion.ts`
интерполирует положение, как это делают сетевые игры.

## Как фронт работает с бэком

- `GET /fleet/snapshot` — состояние парка при подключении: машины, водители, рейсы смены, последние точки, алерты, правила.
- `GET /stream` — SSE с событиями `telemetry`, `alert`, `trip`, `vehicle`. Поток открывается **раньше** снимка,
  а события, пришедшие пока снимок грузится, придерживаются и применяются после него. После обрыва — то же самое заново.
- `PATCH /alerts/{id}` — «Принять». Ответ не применяется напрямую: изменение приходит событием, как у всех диспетчеров.
- Токены: `/login`, `/refresh` (одно обновление на все параллельные 401 — refresh-токен одноразовый), `/logout`.

Подложка — CARTO Dark Matter: бесплатна для некоммерческого использования в пределах их лимитов.
